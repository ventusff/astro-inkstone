## 三层分工

一个用这套东西搭起来的文档/wiki 站,由三方拼成,每一方只管自己那一层:

- **astro-inkbrush(引擎)**:最小 CMS 组件——浏览器里原地块编辑、块级修订史与回滚、评论区、AI 问答/改写/翻译、收件箱导入。它还负责一件看似不属于 CMS 的事:**Markdown 方言与内容守门**。理由很硬:编辑器接受的语法与页面渲染的语法必须是同一套,否则「编辑器里能存、页面上走样」迟早发生,所以解析规则只在引擎里写一份,站点渲染、CMS 保存校验、CI 检查三处共用。
- **astro-inkstone(纸面,即本包)**:观感与管线的共享层——两层设计 token、组件层样式 `base.css`、组件库、markdown 管线预设 `siteMarkdown`、Maple Mono CN 代码字体子集、渲染层体检脚本。它**不做站点身份**:品牌色、布局 chrome、路由、部署都不归它。
- **站点(比如你现在看的这个示范站)**:覆盖 token 第 1 层色板定身份色;自持 Sidebar、导航条这些 chrome(本站的实现就是参考答案);决定内容怎么组织、路由长什么样、部署到哪。

一句话记忆:**引擎管编辑,纸面管观感,站点管身份。**

## 为什么这样切

三条切线各有一条真实约束在背后:

**方言归引擎**,因为检查器的插件集和站点不一致时,比没有检查更糟——缺数学插件的检查器把公式里的花括号误判成 JSX 表达式,不挂 GFM 的检查器对表格里的竖线假放行。语法只写一份,三处消费,永不漂移。

**样式归纸面**,因为多个站点各自维护内容样式表时,同一处对比度修正要挨个改一遍,漏掉哪个,哪个站的小字就不达标。收进共享层之后,修一处,处处生效。

**身份归站点**,因为共享层一旦掺进某个站的品牌色,别的站就得用覆盖去打架。所以 token 分两层:站点只覆盖第 1 层裸色板(`--p-*`),语义层与组件层原封不动跟着走——见「两层色板与主题」一章。

## 站点拿到的东西

从站点视角看,消费本包+引擎,拿到的是:

- `astro-inkstone/styles/tokens.css` + `base.css`:先 token 后组件层,两行 `@import` 拿到全部内容样式;
- `siteMarkdown(...)`:一行接入整条 markdown 管线,选项开关见「安装与接入」;
- `astro-inkstone/components/` 下的组件按需路径导入;
- WIKI 模式下引擎的整套 CMS(本站 `npm run wiki` 即可体验);
- 三道检查:`check-content`、`check-dist`(随引擎)与 `ui_probe`(随本包),见「检查工具一览」。

本站每一页的排版效果,就是这套分工的实际产物——手册即示范。
