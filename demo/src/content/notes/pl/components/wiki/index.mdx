## Wiązanie w trzech linijkach

```ts title="src/lib/taxonomy.ts (całe wiązanie tej witryny)"
import { createTaxonomy } from 'astro-inkstone/lib/taxonomy';
import { DOMAINS, KINDS, STATUSES } from '../content/notes/_meta/taxonomy';

export const { getWikiUnits, groupByKind, groupByDomain, groupByPrimaryDomain, tagIndex, resolveTaxonomy } =
  createTaxonomy({ kinds: KINDS, domains: DOMAINS, statuses: STATUSES },
    { collection: 'notes', locales: [{ code: 'zh', prefix: 'zh/' }], primary: 'en' });
```

Rejestr (`_meta/taxonomy.ts`) to czyste dane w drzewie treści: rodzaje, obszary z parami odcieni, statusy z kolorami kropek, każda wartość z etykietami wyświetlania dla poszczególnych języków. Dodaj tam wartość, otaguj nią notatkę, a każda strona przeglądania podchwyci ją sama — trasy są przecież parametryzowane wartościami.

## Półka i jej tokeny

Strony przeglądania stoją na drugim podłożu: `browse.css` daje im ciepły papier, szeryfową winietę, dwupunktową linię półki i siatkę kart, wszystko przez tokeny `--wb-*` — przeglądową połowę [[design-tokens|palety o dwóch kontekstach]]. Strona wchodzi w ten kontekst jedną klasą, `wb-root`, na swoim body; wewnątrz tokeny chrome’u są przemapowane, więc ten sam pasek nawigacji leży dobrze na każdym z dwóch podłoży.

## NoteCard

Karta przyjmuje dane gotowe do wyświetlenia — rozwiązane etykiety, odcienie, sformatowaną datę, linki do wersji lustrzanych. Karty mieszkają na półce, więc przykład siedzi w skrawku kontekstu przeglądania (`.wb-root.wb-inset`) osadzonym w tej kolumnie lektury:

<div class="wb-root wb-inset">
<ul class="wb-grid">
  <NoteCard
    note={{
      id: 'sample-note',
      href: `${base}/pl/kitchen-sink/`,
      title: 'Wszystko naraz',
      description: 'Każdy element potoku Markdowna występuje na tej stronie dokładnie raz.',
      kind: { id: 'reference', label: 'Referencja' },
      domains: [{ id: 'pipeline', label: 'Potok', tone: { bg: '#e3efec', fg: '#2a6f62' }, href: `${base}/pl/domain/pipeline/` }],
      status: { id: 'evergreen', label: 'Wiecznie zielona', dot: '#1f5e46' },
      updated: '2026.08',
      mirrors: [{ label: 'EN', href: `${base}/kitchen-sink/` }],
    }}
  />
  <NoteCard
    note={{
      id: 'sample-hub',
      href: `${base}/pl/components/`,
      title: 'Zestaw komponentów',

      kind: { id: 'reference', label: 'Referencja' },

## FacetNav

Wielowymiarowy indeks przeglądania — rodzaje, obszary (z ich odcieniami), najczęstsze tagi, wszystko jako wstępnie wyrenderowane pastylkowe linki:

<FacetNav
  base={`${base}/pl`}
  kinds={[
    { def: { id: 'guide', label: 'Przewodnik' }, count: 2 },
    { def: { id: 'reference', label: 'Referencja' }, count: 4 },
    { def: { id: 'pattern', label: 'Wzorzec' }, count: 1 },
  ]}
  domains={[
    { def: { id: 'design', label: 'Design', tone: { bg: '#ece7f2', fg: '#5b4a8a' } }, count: 3 },
    { def: { id: 'pipeline', label: 'Potok', tone: { bg: '#e3efec', fg: '#2a6f62' } }, count: 2 },
  ]}
  tags={[
    { tag: 'tokens', count: 1 },
    { tag: 'markdown', count: 1 },
  ]}
  active={{ dim: 'kind', value: 'reference' }}
  labels={{ kind: 'Rodzaj', domain: 'Obszar', tag: 'Tagi', all: 'Wszystkie →' }}
/>

Etykiety wierszy to również propsy z angielskimi domyślnymi — powyżej przekazano `labels={{ kind: 'Rodzaj', domain: 'Obszar', tag: 'Tagi', all: 'Wszystkie →' }}`, dokładnie to samo, co przekazują polskie strony kategorii tego ogrodu; poza tym nic się nie zmienia.

## TaxonomyLine, KindBadge, StatusDot, DomainChip

Jednolinijkowy pasek metadanych na czele notatki składa się z trzech atomów-odznak; każdego można też użyć osobno:

<TaxonomyLine
  kind={{ id: 'pattern', label: 'Wzorzec' }}
  domains={[{ id: 'design', label: 'Design', tone: { bg: '#ece7f2', fg: '#5b4a8a' }, href: `${base}/pl/domain/design/` }]}
  status={{ id: 'growing', label: 'Rosnąca', dot: '#5c8a3c' }}
  updated="2026.08"
/>

Atomy same, wplecione w bieżący tekst: odznaka rodzaju <KindBadge def={{ id: 'guide', label: 'Przewodnik' }} />, chip obszaru <DomainChip def={{ id: 'pipeline', label: 'Potok', tone: { bg: '#e3efec', fg: '#2a6f62' } }} href={`${base}/pl/domain/pipeline/`} />, kropka statusu <StatusDot def={{ id: 'evergreen', label: 'Wiecznie zielona', dot: '#1f5e46' }} />.

## Backlinks

Panel „linki zwrotne” pod każdą notatką tego ogrodu liczy pakietowe `createBacklinks` — własny resolver wikilinków silnika odwrócony w indeks cel ← źródła, z fragmentami kontekstu włącznie. Tutaj na wbudowanych danych przykładowych:

<Backlinks
  items={[
    {
      href: `${base}/pl/kitchen-sink/`,
      title: 'Wszystko naraz',
      before: 'siedmiokolumnowa tabela jest zarazem ',
      label: 'ściągą calloutów',
      after: ' i testem przełamania na karty…',
    },
    {
      href: `${base}/pl/design-tokens/`,
      title: 'Dwuwarstwowa paleta i motywy',
      before: 'komponenty konsumują wyłącznie ',
      label: 'warstwę semantyczną',
      after: ', więc zmiany tożsamości nigdy ich nie dotykają.',
    },
  ]}
/>

Przewiń do stóp tej strony po ten prawdziwy — ten rozdział sam jest celem wikilinków.

## LocalGraph

Ten sam indeks odpowiada na drugie pytanie — *co jest o jeden skok stąd?* — a `index.localGraph(id, titleOf)` zwraca odpowiedź jako listę sąsiadów, wchodzące najpierw. Komponent rysuje ich na elipsie wokół notatki: wchodzące linią ciągłą, wychodzące przerywaną; sąsiad może nieść własny `color` (na przykład druga kolekcja). Tutaj na szerokość kolumny, z danymi przykładowymi; ten prawdziwy siedzi w sidebarze każdej notatki, która ma linki:

<div style="max-width: 300px">
  <LocalGraph
    centerTitle="Wiki i przeglądanie"
    neighbors={[
      { id: 'kitchen-sink', title: 'Wszystko naraz', href: `${base}/pl/kitchen-sink/`, dir: 'in' },
      { id: 'design-tokens', title: 'Dwuwarstwowa paleta', href: `${base}/pl/design-tokens/`, dir: 'out' },
      { id: 'three-way-split', title: 'Trójpodział', href: `${base}/pl/three-way-split/`, dir: 'out' },
      { id: 'checks', title: 'Kontrole', href: `${base}/pl/checks/`, dir: 'in', color: 'var(--color-accent4)' },
    ]}
  />
</div>
