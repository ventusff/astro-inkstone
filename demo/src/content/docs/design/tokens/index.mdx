## Two tiers

`styles/tokens.css` is the single source of truth for the site's colors, in two tiers:

**Tier 1: the raw palette** — constants named after paper and ink pigments, unchanged across themes. Papers: plain, silk, page, slip, note (page ground / soft surface / card face / code ground / math ground); inks: black, blue-black, faint, hairline; pigments: vermilion, indigo, ochre, violet; plus a dedicated "night" and "moon-white" set for dark. Variables start with `--p-`:

```css title="tokens.css (tier 1, excerpt)"
--p-paper: #fbf9f4; /* plain · page ground */
--p-ink: #25313a; /* black · body text */
--p-vermilion: #c14b02; /* vermilion · primary accent (AA-darkened, 4.7:1) */
--p-vermilion-raw: #fe5d01; /* vermilion · raw (glyphs/graphics only, never body links) */
```

**Tier 2: semantic tokens** — purpose-named variables like `--color-bg`, `--color-ink`, `--color-accent`. Light points them at tier 1 in `:root`; dark re-points the whole set inside `[data-theme='dark']`. **The component layer (`base.css` and every component) may consume only this tier** — new rules must not contain raw color values. That is the package's hard discipline.

## How a site customizes identity

Override tier 1. Swap `--p-vermilion` for your brand color and the semantic and component layers follow untouched — both themes at once:

```css title="your site.css"
:root {
  --p-vermilion: #b03a48;
  --p-vermilion-text: #93303c; /* the small-text step is darkened separately, see below */
}
```

(Re-mapping tier-2 semantic tokens onto your own palette is equally supported when your design system already has one.) This demo deliberately overrides nothing — what you are reading is the package's bare face.

## Contrast is audited

Every value in the tokens is vetted for WCAG AA on every background it sits on: small text starts at 4.5:1; accent colors get an independently darkened **text step** (`--p-vermilion-text`, `--p-mustard-text`), because when the accent orange is used for 12.5px labels its background is often its own light tint; the dark theme carries its own brightened set. Before changing any value, know every surface it sits on.

## Light is the identity

The theme deliberately does **not** read `prefers-color-scheme`: a page must never flip its own theme under the reader. Dark activates only through `[data-theme='dark']`, toggled by the site's own switch (the sun/moon button at the right of this site's nav bar; the choice is stored under the `inkstone-theme` key in `localStorage` and replayed by the ThemeInit inline script before first paint, so dark-theme readers never see a cream flash).

## Fonts live here too

The code font is a fixed-charset subset of Maple Mono CN (ASCII + box-drawing + the common-3500 Hanzi + the union of existing content): Latin at 0.6em, Hanzi at 1.2em — **a Hanzi is exactly two character cells wide**, so box-drawing diagrams align even in mixed Chinese/Latin text. The subset recipe and regeneration script ship with the package (`fonts/build_font_subset.py`); when content needs glyphs beyond coverage, re-run it and commit the woff2. The body serif and UI sans stacks are defined in the tokens as well (`--font-body`, `--font-ui`, `--font-mono`).
