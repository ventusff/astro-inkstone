## 編集の一巡

描画済みのブロックが隠れ、その位置に [CodeMirror](https://codemirror.net/) のエディタが展開して、そのブロックの Markdown ソースを抱えます。打鍵に合わせて、その下でライブプレビューが描画されます——エンジンの方言に、サイトが `inkbrush({ markdown })` へ手渡すプラグインを重ねたもの、つまりページのパイプラインが積んでいるのと同じ規則一式を通るので、プレビューとページが食い違うことはあり得ません。`⌘/Ctrl + Enter` で保存、`Esc` でキャンセルです。

frontmatter もひとつのブロックです:このサイトのすべてのノートの頭にある分類ストリップは自分の ✎ を持ち、クリックするとノートの YAML が開きます——status や日付を変えれば、ヘッダは更新後の frontmatter から描画し直されます。

## 二つの安全網

**楽観的ロック。** 各ブロックは、自分が切り出された元ソースのハッシュを携えています。あなたの足元でほかの誰かがファイルを変えていたら、保存は相手の仕事を黙って上書きせず、競合として拒否されます——リロードしてやり直してください。

**ビルド関門。** 何かがディスクに書かれる前に、ファイル全体がサイトの Markdown パイプラインを通ります——方言、コンテンツガード、サイト自身のプラグイン、そして `.mdx` なら MDX コンパイラまで。ページを壊す保存——対を作れない `**`、閉じ忘れたコンポーネントタグ、不正な式——は正確なエラーとともに拒否され、ディスク上のファイルは手つかずのまま残ります。ガードの拒否リストの全容は[[kitchen-sink|全部入りデモ]]の巻末で実演されています。

## 保存はどこへ行くか

保存は Markdown ファイルを書き、`autocommit` が有効なら、サインイン中のユーザーを author とする git コミットになります。データベースはどこにもありません:コンテンツファイルが唯一の情報源で、git が耐久性のある履歴です。[[inkbrush/revisions|変更履歴]]を動かしているブロック単位の細粒度ジャーナルは、その上に載っています。

方言そのもの——CJK フレンドリーな強調規則を備えた GFM に、静かに変形する Markdown を拒むコンテンツガードを重ねたもの——はエンジンの中に一度だけ定義され、ページのレンダラ、このエディタのプレビュー、そして `check-content` CLI([[checks|五つのチェック]])が共有します。一つの文法、三つの消費者、ドリフトはゼロ。
