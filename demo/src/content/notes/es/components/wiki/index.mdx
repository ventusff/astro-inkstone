## La vinculación, en tres líneas

```ts title="src/lib/taxonomy.ts (toda la vinculación de este sitio)"
import { createTaxonomy } from 'astro-inkstone/lib/taxonomy';
import { DOMAINS, KINDS, STATUSES } from '../content/notes/_meta/taxonomy';

export const { getWikiUnits, groupByKind, groupByDomain, groupByPrimaryDomain, tagIndex, resolveTaxonomy } =
  createTaxonomy({ kinds: KINDS, domains: DOMAINS, statuses: STATUSES },
    { collection: 'notes', locales: [{ code: 'zh', prefix: 'zh/' }], primary: 'en' });
```

El registro (`_meta/taxonomy.ts`) es datos puros dentro del árbol de contenido: tipos, dominios con sus tonos, estados con el color de su punto, cada uno con un rótulo en inglés y otro en chino. Añade allí un valor, etiqueta una nota con él y todas las páginas de exploración lo recogen — las rutas están parametrizadas por valor.

## La estantería y sus tokens

Las páginas de exploración viven sobre un segundo fondo: `browse.css` les da el papel cálido, la cabecera con serif, la regla de dos puntos de la estantería y la cuadrícula de tarjetas, todo a través de los tokens `--wb-*` — la mitad de estantería de [[design-tokens|la paleta de dos contextos]]. Una página entra en el contexto con una sola clase, `wb-root`, en su body; dentro, los tokens del chrome se reasignan para que la misma barra de navegación se asiente sobre cualquiera de los dos fondos.

## NoteCard

## FacetNav

El índice de exploración multidimensional — tipos, dominios (con sus tonos), etiquetas destacadas, todo como enlaces-píldora prerenderizados:

<FacetNav
  base={`${base}/es`}
  kinds={[
    { def: { id: 'guide', label: 'Guía' }, count: 2 },
    { def: { id: 'reference', label: 'Referencia' }, count: 4 },
    { def: { id: 'pattern', label: 'Patrón' }, count: 1 },
  ]}
  domains={[
    { def: { id: 'design', label: 'Diseño', tone: { bg: '#ece7f2', fg: '#5b4a8a' } }, count: 3 },
    { def: { id: 'pipeline', label: 'Pipeline', tone: { bg: '#e3efec', fg: '#2a6f62' } }, count: 2 },
  ]}
  tags={[
    { tag: 'tokens', count: 1 },
    { tag: 'markdown', count: 1 },
  ]}
  active={{ dim: 'kind', value: 'reference' }}
  labels={{ kind: 'Tipo', domain: 'Dominio', tag: 'Etiquetas', all: 'Todas →' }}
/>

Los rótulos de fila también son props, con valores por defecto en inglés — el ejemplo de arriba pasa `labels={{ kind: 'Tipo', domain: 'Dominio', tag: 'Etiquetas', all: 'Todas →' }}`, lo mismo que pasan las páginas de facetas en español de este sitio; nada más cambia.

## TaxonomyLine, KindBadge, StatusDot, DomainChip

La franja de metadatos de una línea a la cabeza de una nota ensambla los tres átomos de insignia; cada uno también se usa por separado:

<TaxonomyLine
  kind={{ id: 'pattern', label: 'Patrón' }}
  domains={[{ id: 'design', label: 'Diseño', tone: { bg: '#ece7f2', fg: '#5b4a8a' }, href: `${base}/es/domain/design/` }]}
  status={{ id: 'growing', label: 'En crecimiento', dot: '#5c8a3c' }}
  updated="2026.08"
/>

Los átomos por su cuenta, dentro de una línea corrida: una insignia de tipo <KindBadge def={{ id: 'guide', label: 'Guía' }} />, un chip de dominio <DomainChip def={{ id: 'pipeline', label: 'Pipeline', tone: { bg: '#e3efec', fg: '#2a6f62' } }} href={`${base}/es/domain/pipeline/`} /> y un punto de estado <StatusDot def={{ id: 'evergreen', label: 'Perenne', dot: '#1f5e46' }} />.

## LocalGraph

El mismo índice responde una segunda pregunta — *¿qué hay a un salto de aquí?* — y `index.localGraph(id, titleOf)` la devuelve como una lista de vecinos, primero los entrantes. El componente los dibuja sobre una elipse alrededor de la nota, los entrantes con trazo continuo y los salientes con trazo discontinuo; un vecino puede traer su propio `color` (una segunda colección, por ejemplo). Aquí al ancho de la columna, con datos de ejemplo; el de verdad está en el sidebar de cada nota que tiene enlaces:
