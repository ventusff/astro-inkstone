## 有効にする

受信箱は既定でオフです。`inkbrush.config.ts` で有効にします:

```ts title="inkbrush.config.ts"
inbox: {
  dir: '~/vault/inbox',        // 監視するフォルダ(~/ が使えます)
  ignore: ['daily-'],          // 任意:読み飛ばすファイル名の接頭辞
},
```

起動時にすでにフォルダにあったファイルは「見た」と印を付けられるだけで、取り込まれません——自動で同期されるのは、*その後に*追加されたノートだけです。それより古いものは API から明示的に遡って取り込めるので、受信箱をオンにした途端に十年分の vault の歴史がサイトへ雪崩れ込む、という不意打ちは起きません。

## インポータがすること

届いたノートは一つずつ、コピーされるのではなく変換されます:

- 画像の埋め込みは vault のアセットフォルダに対して解決され、ファイルは**取り込まれたノートの隣にコピーされ**、埋め込みは標準の画像記法になります——後でノートを消せば、そのアセットも一緒に消えます
- サイト上の実在ノートに一致する `[[ウィキリンク]]` は、[[inkbrush/wikilinks|ほかのあらゆる場所と同じ規則]]で解決されてリンクのまま生き残ります。残りは警告付きで、ただの強調に均されます
- ハイライトは本物の `<mark>` 要素になり、frontmatter のメタデータはタイトル下の出典行になり、説明文は最初の実質的な段落から導かれます

変換されたノートはその後、手動保存と同じビルド関門を通らなければなりません——ページを壊すノートは、取り込まれる代わりに拒否されます。

すべての取り込みは、ファイル丸ごとの記録としてリビジョンジャーナルに残ります(via: inbox)。[[inkbrush/revisions|⟲]] はそれを監査行として列挙し、取り込みの取り消しは git の操作です。`autocommit` がオンなら、各取り込みはほかの編集と同じように git コミットにもなります。オフなら、取り込まれたファイルは普通の作業ツリーの変更として届くので、自分でレビューしてコミットします。
