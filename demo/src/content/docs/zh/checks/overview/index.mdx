## 三道守门,各守一层

构建绿灯不等于页面没事。这套工具链在三个层面各设一道检查,每一道各抓一类「构建照绿、页面已坏」的静默失败:

| 检查 | 随哪个包 | 看什么 | 什么时候跑 |
| --- | --- | --- | --- |
| check-content | 引擎 `scripts/check-content.mjs` | 每个 md/mdx 源文件 | 内容仓 CI,或写作后 |
| check-dist | 引擎 `scripts/check-dist.mjs` | `astro build` 的产物 | 每次构建后(postbuild) |
| ui_probe | 本包 `scripts/ui_probe.mjs` | 真实浏览器渲染出的页面 | 样式/布局改动后 |

## check-content:源码这一层

把每个要上页面的 md/mdx 用与站点**完全同一份方言**真编译一遍——语法错、静默变形(配不上对的强调标记、被 MDX 求值吃掉的花括号、折行折出的项目符号、单行 `$$`、KaTeX 渲不出的公式)一律让 CI 红。

为什么必须由引擎出这份脚本:检查器的插件集和站点不一致时,**比没有检查更糟**——缺数学插件的检查器会把公式里的花括号误判成 JSX 表达式,不挂 GFM 的检查器对表格假放行。方言只在引擎里写一份,站点渲染、CMS 保存校验、这里,三处永远同一套。

```bash title="内容仓根目录"
node <engine>/scripts/check-content.mjs . --glob '**/index.{md,mdx}' --math
```

除编译外还查两类 frontmatter 静默丢失:值里未加引号的井号(YAML 把它当注释,后半句被静默截掉)与 CRLF 换行(frontmatter 正则只认 LF,标题静默回退成 slug)。

## check-dist:产物这一层

构建出来的 `dist/` 里,读者点得到的每个站内引用都必须真的存在。抓的是构建绿灯之下的静默残缺:

- 站内链接/资源指向不存在的文件(链接大改版后成片 404 的那类);
- 页内锚点指向不存在的 id;
- 路径里叠出重复的语言段(`/en/en/`——i18n 路由兜底给已带前缀的路径再叠前缀的典型病);
- `<a>` 嵌套 `<a>`(HTML 解析器会提前闭合外层,按钮被甩出卡片);
- KaTeX 渲染错误残留(公式在页面上是红字,而构建照绿)。

本示范站把它挂在 postbuild:`npm run build` 全绿即代表产物检查也过了。

```bash title="站点根目录,build 之后"
node vendor/astro-inkbrush/scripts/check-dist.mjs dist
```

## ui_probe:渲染这一层

源码和产物都对,页面照样可能坏——典型如首页卡片没有任何样式规则命中,整段以裸文本挤成一行:链接/锚点体检全绿,因为它们从没看过渲染出来的页面。`ui_probe` 用真实浏览器对 `dist` 里每个页面、四档视口宽度(1440/1024/768/430)逐一量:横向溢出、无样式类、死锚点、标题跳级、缺 alt 的图。只报机器能确证的东西,不做审美判断。

```bash title="需要本机有 Chrome/Chromium"
npm run build
node ../scripts/ui_probe.mjs dist   # 自带静态服务;要体检线上站点就传 baseUrl 参数
```

全绿的判据是报告最后一行 `PAGES WITH FINDINGS: 0`。
